# Research Dashboard Guide

Run the dashboard from the project root:

```powershell
.\scripts\run_dashboard.ps1
```

The script first synchronizes the current `events/` objects from S3, rebuilds `analytics/pipeline.duckdb`, and then opens the Streamlit dashboard.

## Six sections

### 1. Overview
Operational summary of the actual stored S3/DuckDB output: stored event count, selected AWS-run success rate, distinct event types, average pipeline processing time, latest processed timestamp, event trend, event mix, recent records, and CloudWatch telemetry when available.

### 2. Event Analytics
Interactive type/source filtering over the synchronized event dataset, including event distribution, value histograms, box plots, processing-time distribution, recent filtered records, and analytics-import quality/rejected-file counts.

### 3. Baseline vs AWS
Reads the selected run's `baseline_summary.json`, `aws_summary.json`, `comparison.json`, raw traces and the associated `<run>-saturation` evidence. It visualizes throughput, p50/p95/p99 latency, error rate, throughput-vs-concurrency, p95-vs-concurrency and raw latency distributions.

### 4. Cold Start Analysis
Reads `cold_start_trials.csv` generated by the cold-start campaign. It shows trial count, success rate, p50/p95/p99, a latency histogram, latency by trial and NT-1 acceptance evidence.

### 5. Cost Analysis
Reads `cost_analysis.json` plus the captured pricing snapshot. It separates measured Lambda usage from declared request-count bounds and from the modeled always-on reference cost. It shows component costs, normalized cost/event, usage evidence, assumptions and limitations. Incomplete pricing remains visibly `HOLD`.

### 6. Negative Tests
Reads `negative_tests/nt-1.json` through `nt-5.json`. It shows PASS/HOLD/FAIL totals and exposes expected behavior, observed result, recovery action, recovery time, residual risk and evidence path for each test.

## Run selector

The sidebar automatically prefers complete experiment runs over individual saturation child runs. Selecting a run scopes the performance, cold-start, cost, CloudWatch and negative-test evidence. Stored-event analytics always reflects the current synchronized S3 dataset.

## No placeholder measurements

The dashboard never invents experimental values. When a required evidence artifact is not present, the relevant section displays an unavailable/HOLD state and tells you which experiment must be run.
